# Documentation change workflow

## Plan

Identify the target chapter, learner outcome, related README links, and any time-sensitive claims.

## Edit

Make a minimal change that preserves the numbered sequence, terminology, and GFM style.

## Validate

Check changed local links, anchors, headings, fences, footnotes, images, and YAML syntax when agent files change.

## Verify

Use official Google sources for current product facts. Inspect the diff and confirm only intended files changed.

## Finish

Report the files changed, checks performed, unresolved uncertainty, and an appropriate Conventional Commit type. Never report deployment or external validation without evidence.
