# Repository Agent Rules

1. Treat the repository as a learning workspace that is moving toward a real project, not as permanently documentation-only.
2. Inspect the actual tree and configuration before assuming the runtime, framework, package manager, or test command.
3. Preserve the codelab's numbered progression and learner-facing tone while learning material remains in scope.
4. Before coding new behavior or changing architecture, require a clear plan and acceptance criteria.
5. If requirements or phase are unclear, stop and ask focused clarification questions; do not fill gaps with assumptions.
6. Check every changed internal link and every changed external claim.
7. Use official Google sources for current AI Studio, Cloud Run, DNS, billing, quota, and cleanup facts.
8. Never expose credentials or ask a user to paste secrets into chat.
9. Do not claim validation, deployment, or completion without evidence.
10. Prefer links to existing repository documentation over duplicated prose.
11. Keep transcript edits separate from canonical tutorial edits when possible.
12. If a requested integration is not configured, document it as a recommendation rather than activating it.
