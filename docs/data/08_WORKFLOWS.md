# Workflows

## Study Workflow
1. Gather source materials.
2. Organize them by course/module.
3. Convert lectures into structured Markdown notes.
4. Extract key concepts and examples.
5. Create recitation/presentation material when needed.
6. Store durable outputs in repositories and/or knowledge-management systems.
7. Track activity and progress separately from future references.

## AI-Assisted Development
- Maintain reusable prompts, skills, templates, and context files.
- Use a shared context architecture across AI coding environments.
- Reduce consistency drift between Copilot, Claude, Gemini CLI, and other tools.
- Prefer portable Markdown-based context.

## Project Workflow
- Use the Universal Project Build Template.
- Separate Academic, Portfolio, and Client/Delivery tracks.
- Flag invalid or contradictory requests before acting.
- Avoid unrequested scope expansion.
- Treat additions as additive where the project rules require it.
- Increment document/template versions after updates.

## GitHub Workflow
- Use repositories as durable context.
- Use GitHub Actions for repeatable automation.
- Validate builds and links before redeployment.
- Prefer public repository references for stable project context.

## Knowledge Management
- Notion handles structured learning/project records.
- Obsidian supports personal knowledge organization using PARA.
- Markdown acts as the portable interchange format.
